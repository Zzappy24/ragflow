# Upstream monolithic chart — kept as reference, NOT deployed

This is the upstream RAGFlow Helm chart (`infiniflow/ragflow` — `helm/`)
preserved here for reference. It is **not** the chart we deploy in production.

## Why we don't use it as-is

| Concern | Upstream chart | Our needs |
|---|---|---|
| Tenancy | Single-tenant (1 deployment per cluster) | **Multi-tenant SaaS**: one cluster serves N workspaces (Bodemer + future clients) |
| Replicas | StatefulSets `replicas: 1` | HA across the board (3× MariaDB Galera, 3× Redis, 4× MinIO EC) |
| Autoscaling | None | HPA on api, KEDA on task_executor (scale on Redis stream length) |
| Storage | Single PVCs, `rook-ceph-block` (RWO) | Same RWO storage class but layout per operator best-practice |
| Routing | `Ingress` v1 | **Gateway API** (Envoy Gateway is the cluster ingress) |
| Database | StatefulSet MySQL bare | **MariaDB Operator** (Galera, automated backups) |
| Redis | StatefulSet Redis bare | **redis-operator** (Sentinel HA, persistence) |
| Object store | StatefulSet MinIO bare | **MinIO Operator** Tenant CR (encryption-at-rest, scale-up live) |
| Secrets | Plain `Secret` baked into the chart | **External Secrets Operator** sourcing from Vault |
| Build/deploy | Manual `helm install` | **GitOps via ArgoCD**, image built by GitLab CI, pushed to Harbor |

The upstream chart is fine for a quick POC (which is what's currently
running in the `gpt` ns under release `ragflow-test`) but doesn't meet the
production requirements above.

## Where we deploy from

See `helm/ragflow/` for the Cyllene production chart (umbrella with
sub-charts) and `argocd/` for the ArgoCD `Application` manifests.
